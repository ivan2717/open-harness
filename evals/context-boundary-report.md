# 1M 上下文边界实测

测试日期：2026-10-22（Asia/Shanghai）。使用生产 `agent_providers::HttpModel`，DeepSeek Chat Completions 与 OpenAI Responses 均配置 high 思考、8,192 输出上限。未使用 tokenizer 或额外计数请求。

## 真实超限后的完整恢复

额外用 OpenAI 执行了两轮真实会话，整个过程没有替换模型窗口、计数器、策略或错误：

1. 首轮实际输入 **892,482**，成功回答并建立真实 usage 锚点。
2. 追加 4,096 行不含答案的记录。本地校准预测 **924,352**，加余量后的决策值 **929,133**，低于默认触发点 945,000，因此实际发送；服务端确实返回 `ContextOverflow`。
3. 执行循环只发起一次恢复。摘要请求实际输入 **892,673**，其中 **892,479** 命中缓存；生成摘要后只重试一次。
4. 重试实际输入 **33,162**，三个历史事实全部正确，原始日志完整。共 4 次模型调用、1 次真实超限、1 次摘要、1 次最终重试，总耗时 36.86 秒。

这条链路也验证了接近边界时缓存友好的原前缀摘要路径。其余百万级历史场景验证的是分批摘要路径。原始证据：[真实超限恢复记录](results/openai-context-overflow-recovery-20261022.json)。

## 本次发现并修复的问题

1. **DeepSeek 超限漏判**：真实响应使用通用 `invalid_request_error`，容量信息位于消息中。适配器现在仅对 HTTP 400/413、完整已知模板和一致的 token 算术关系识别超限，不做宽泛关键词匹配。真实复跑已返回 `ContextOverflow`。
2. **流式业务错误被当作解析错误**：OpenAI 用 HTTP 200 + SSE `error` / `response.failed` 返回超限。适配器现在保留脱敏的结构化错误类别；同样覆盖 JSON 业务错误以及其他协议的结构化流式错误。真实约 92.4 万目标请求复跑已返回 `Rejected { ContextOverflow }`。

这些错误可以进入执行循环的有限压缩恢复流程；已经输出部分内容的请求不会自动重放。错误对象不保留提供方原文、提示词、密钥或 URL。评估专用诊断仅对合成语料记录有限、脱敏的错误详情。

## 计数误差与适用范围

这组长 ASCII 语料中，原始 UTF-8 估算约低估 **3.12%**；加默认 15% 不确定性余量后，决策值约高于实际 **11.4%**。因此默认策略会提前压缩，不能把决策值直接理解为实际 token 数。不同语言、代码、工具 schema 和思考状态的误差可能不同，这不是通用误差上界。

三个标记校验只覆盖事实保留，不能替代对摘要目标、计划和约束的完整语义评估。

这是一组有界的容量与恢复测试，未测试持续并发、速率限制、长时间稳定性、图片或音频输入。桌面的单条输入长度限制不在本轮测试范围；大历史直接通过核心运行时构造。
