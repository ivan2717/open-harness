父任务在拿到自动完成消息后触及预算护栏，未创建最终 JSON，因此无法验证最终 JSON 数字、引用或读回检查。

- 子任务 `read parent offset=0 limit=20` 返回 19 条消息、21,407 字节，除了有效原文还包含四段无关归档及父任务工具结果。
- 父任务在子任务执行时 `read child offset=0 limit=10` 又取回 14,025 字节，其中包括 handoff 和子任务已读取的父历史。这是嵌套历史重复进入模型上下文。

父任务的协作序列为 `list → wait(30s) → read child → list → send → wait`。最后的 send 没有新约束，只是发送父任务已核算数字并催促完成。子任务此时已执行完脚本、正在形成详细报告；收到消息后又生成了一轮简短确认。完成通知只引用最后的简短答复，原详细报告中的脚本路径和完整命令未包含在自动通知里，父任务若继续还需要定向核验。

## 后续重点

保持该失败记录和原预算。优先减少协作读取的总载荷，支持通过已知消息 ID 定向回查，避免默认把嵌套工具结果和无关历史整段回灌；协调器已经完成独立核验时，应等待自动结果而不是无信息增量的催促。终态通知应能指向可核验的结果来源，避免最后一句简短确认遮蔽真正的交付证据。
